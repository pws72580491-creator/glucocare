# 글루코케어 Pro (GlucoCare Pro) — v1.0.0

혈당·혈압·체중·식단·운동·약물을 한곳에서 기록하는 통합 건강관리 PWA입니다.
바닐라 JS + IndexedDB로 만든 오프라인 우선 구조이며, 외부 UI 프레임워크 의존성이 없습니다.

## 실행 방법

Service Worker와 일부 최신 API는 `file://`로 직접 열면 동작하지 않을 수 있습니다.
로컬 웹서버로 열어주세요.

```bash
cd glucocare
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080 접속
```

배포 시에는 정적 호스팅(Firebase Hosting, Netlify, Vercel 등) 아무 곳이나 사용 가능합니다.
모바일 브라우저에서 "홈 화면에 추가"를 하면 PWA로 설치됩니다.

## 폴더 구조

```
glucocare/
├─ index.html          대시보드 · 기록 · 그래프 · 리포트 · 공유 화면
├─ manifest.json        PWA 매니페스트
├─ sw.js                오프라인 앱 셸 캐싱
├─ css/style.css        전체 스타일
├─ js/db.js             IndexedDB 저장소 래퍼
├─ js/foodDb.js         한식 영양 참고 테이블 + 이름 기반 자동 매칭
├─ js/charts.js         캔버스 기반 차트 렌더러 (외부 라이브러리 없음)
├─ js/insights.js       예상 당화혈색소, 목표범위 유지율, 식사-혈당 매칭 계산
└─ js/app.js            화면 라우팅 및 전체 조립
```

## 지금 바로 되는 기능

- 혈당·혈압·체중·식단·운동·약물 통합 기록 (IndexedDB, 오프라인 저장)
- 오늘의 대시보드: 평균 혈당, 목표범위 여부, 하루 타임라인(식사·혈당 함께 표시)
- 식사 이름 입력 시 로컬 영양 테이블(`foodDb.js`)에서 자동 매칭 → 탄수화물/단백질/지방/나트륨/GI 자동 채움 (수동 보정 가능)
- 간단한 휴리스틱 기반 "식사 점수"와 식후 혈당 변화(Δ) 표시
- 7/30/90일 그래프(혈당·혈압·체중), 목표범위 밴드 표시
- 예상 당화혈색소(eA1C) — ADAG 연구 공식 기반 (참고용, 실제 진단 아님)
- 리포트: 기간 통계 요약, 혈당 분포, 인쇄/PDF 저장(브라우저 인쇄 기능), CSV 내보내기
- 공유 코드 생성 UI (기기 내 저장까지만 — 아래 "다음 단계" 참고)

## 자리만 마련되어 있고, 연동이 필요한 기능

원본 기획서에 있는 아래 기능들은 브라우저 표준 API만으로는 구현이 불가능하거나
서버/네이티브 앱 계층이 필요해서, 지금은 UI와 데이터 구조만 준비해두고
실제 하드웨어·API 연동은 다음 단계로 남겨두었습니다.

| 기능 | 왜 지금은 안 되는지 | 다음 단계 |
|---|---|---|
| 사진 → 실제 AI 음식 자동 인식 | 이미지 분류에는 비전 모델 API 호출이 필요 (정적 페이지만으론 불가) | "발주관리" 앱에서 쓰신 Gemini API 패턴처럼, 사진을 base64로 인코딩해 Vision 모델에 전달 → 반환된 음식명을 `FoodDB.matchByName()`에 넘기면 지금 UI에 바로 연결됩니다 |
| CGM(프리스타일 리브레 등) 실시간 연동 | 각 제조사 전용 BLE 프로토콜/클라우드 API 필요, 브라우저 표준으로는 접근 불가 | 제조사 공식 SDK가 있는 네이티브 앱(iOS/Android) 또는 해당 업체 클라우드 API 서버 연동 필요 |
| 애플 건강 / 구글 헬스 커넥트 / 핏빗 | HealthKit·Health Connect는 네이티브 전용 API (웹에서 접근 불가) | React Native, Capacitor 등으로 네이티브 래핑 후 해당 SDK 연동 |
| 가족·의료진 실시간 공유·채팅 | 실시간 동기화에는 백엔드(서버 또는 Firebase 같은 BaaS)가 필요 | 아래 "Firebase 연동" 참고 |

## Firebase 연동 (실시간 동기화 · 실제 공유 기능을 원할 때)

지금은 모든 데이터가 기기 안 IndexedDB에만 저장됩니다. 기존에 만드신 다른 앱들처럼
Firebase Realtime Database를 붙이려면:

1. `js/db.js`의 `add()` 함수 안에서, 로컬 저장 성공 후 동일한 데이터를 Firebase에도 `push()`
2. 공유 코드(`shareCode`)를 Firebase 경로의 키로 사용해, 같은 코드를 가진 사용자끼리 데이터를 구독
3. 가족·의료진 채팅은 `/shares/{code}/messages` 같은 경로에 메시지를 추가/구독하는 방식으로 확장

호출부(`app.js`)는 그대로 두고 `db.js` 내부만 바꾸면 되도록 함수 인터페이스를 설계해두었습니다.

## 데이터 백업

- 리포트 탭 → CSV 내보내기: 최근 30일 전체 기록을 CSV로 저장
- 리포트 탭 → PDF로 저장: 브라우저 인쇄 기능으로 요약 리포트를 PDF로 저장하거나 진료 시 바로 인쇄

## 참고

- 예상 당화혈색소는 참고용 추정치이며, 실제 진단은 반드시 의료기관 검사로 확인해야 합니다.
- 식사 점수·영양 자동 매칭은 대략적인 참고 수치이며, 실제 섭취량과 다를 수 있습니다.
- 목표범위 판정(`insights.js`의 70–140mg/dL)은 단순화를 위해 측정 시점과 무관하게 하나의 기준을 사용합니다.
  실제로는 공복/식전/식후 기준치가 다르므로, 정확도가 필요하면 `GLUCOSE_TARGET`을 컨텍스트별 값으로 분리하는 것을 권장합니다.
